网络协议的“三要素”

目标：下次看到“时序 / 时延”时，不靠背答案也能排除。

原题答案：B，语法、语义、时序。
你选了 D，说明“语法”记住了，但把“语义”换成了“时延”。

先建立一个判断框架

语法 = 形数据和控制信息采用什么格式、字段如何排列。

如 TCP 首部各字段的位数与位置。

语义 = 意字段、取值或动作代表什么，以及接收方应做什么。

如 SYN 表示请求同步序号。

时序 = 序事件在什么条件下发生，谁先谁后，收到消息后如何响应。

如 SYN → SYN+ACK → ACK。

口诀：语法看“形”，语义看“意”，时序看“先后”。

为什么不是“时延”

时延回答“花了多久”，属于性能度量；时序回答“何时发生、先后如何”，属于交互规则。协议必须规定双方怎样配合，但其三要素不把网络快慢列为一项。

迁移到真实协议：TCP 三次握手

语法：TCP 报文首部存在 SYN、ACK 等标志位。
语义：SYN=1 和 ACK=1 各自具有约定含义。
时序：客户端先发 SYN，服务端回 SYN+ACK，客户端再回 ACK。
时延：完成握手需要多长时间——这是性能结果，不是三要素。

闭卷小测

先不要上翻：网络协议三要素通常是（ ）。

权威延伸

推荐浏览 RFC 9110 的引言：它把 HTTP 的通信语法、接收消息的意图（语义）和接收方预期行为明确区分开。再看 RFC 9293 的 TCP 报文格式与状态机，把三要素落到真实协议上。
