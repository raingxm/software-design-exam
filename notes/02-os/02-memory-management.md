# 存储管理 (Memory Management)

存储管理主要负责内存的分配、保护、扩充和地址映射。

## 1. 地址映射 (Address Mapping)

- **逻辑地址 (Logical Address)**：程序中使用的相对地址。
- **物理地址 (Physical Address)**：内存中的实际地址。
- **重定位 (Relocation)**：将逻辑地址转换为物理地址的过程。

---

## 2. 存储分配方式

### 2.1 页式存储 (Paging)
将内存分为固定大小的 **页框 (Page Frame)**，程序分为同样大小的 **页 (Page)**。
- **优点**：利用率高，**无外部碎片**（任意空闲框都能装页）。
- **缺点**：增加了开销；可能产生 **内部碎片**（最后一页装不满）。
- **地址结构**：页号 + 页内偏移。

#### 地址转换计算 (软考核心考点)
1. **识别页面大小**：若页面大小为 4KB，则页内偏移占 12 位（$2^{12} = 4096$）。
2. **拆分逻辑地址**：逻辑地址 = 页号 + 页内偏移。
   - **例（十六进制）**：地址 `5A29H`，页大小 4KB，则页号为 `5`，偏移为 `A29H`。
   - **例（十进制 · 2026 上半年真题）**：页面 4K，逻辑地址 `9000`，页表 0→3、1→2、2→5。
     页号 = 9000 ÷ 4096 取整 = **2**；页内 = 9000 − 2×4096 = **808**；查表页号 2 → 帧 **5**；
     物理 = 5×4096 + 808 = **21288**。
3. **查页表**：根据页号找到对应的**物理块号**（先做越界检查：页号 ≥ 页表长度 → 越界中断，不查表）。
4. **拼接地址**：物理地址 = 物理块号 + 页内偏移。

> **口令：页内偏移永不变，只换高位页号→帧号。**（与 Cache 的 tag|组|块内、段式的段号|段内同构——「高位标识 | 低位偏移」分解，变换只动高位）
> 十六进制快解：4K → 低 12 位是偏移。9000 = `0x2328` → 页 `2` / 偏移 `328`；帧 5 → `0x5328` = 21288。
> 陷阱：① 答案=原地址（没变换）② 帧号查错行 ③ 页内只减一个 4096。

#### 页表项 (Page Table Entry)
- **状态位**：1 表示在内存，0 表示不在（缺页）。
- **修改位**：决定页面换出时是否需要写回磁盘。

### 2.2 段式存储 (Segmentation)
按程序的逻辑结构划分为若干个 **段 (Segment)**，各段大小不等。
- **优点**：逻辑独立，利于共享和保护。
- **缺点**：主要产生 **外部碎片**（空闲区碎，大段放不进）。
- **地址结构**：段号 + 段内偏移。

### 2.3 段页式存储 (Segmented Paging)
结合两者优点：先分段，段内再分页。
- **地址转换**：段表 -> 页表 -> 物理内存。
- **碎片**：内部、外部都可能有，但通常较小。

> 对照表与记忆法见 [回顾 · 页/段碎片](./04-os-review.md#五存储管理计算题高发)。

## 3. 虚拟存储技术 (Virtual Memory)

基于程序的 **局部性原理 (Principle of Locality)**。

### 页面置换算法
当内存缺页且页框已满时，需要选择一页换出：
1. **最佳置换算法 (Optimal)**: 理论最优，淘汰以后最长时间不再访问的页。
2. **先进先出 (FIFO)**: 可能产生 **Belady 异常**（分配页框越多，缺页率反而越高）。
3. **最近最久未使用 (LRU)**: 性能接近 Optimal，是实际应用中最常用的。

> 深化：[FIFO / LRU 手算与 Belady 异常](../deep-dives/13-page-replacement-tutorial.md)

## 4. 磁盘管理

- **存取时间** = 寻道时间 + 等待时间 (旋转延迟) + 传输时间。
- **磁盘调度算法**:
    - FCFS (先来先服务)
    - SSTF (最短寻道时间优先)
    - SCAN (电梯：到**边界**再反向)
    - LOOK (到当前方向**最后一个请求**再反向)

> 深化：[SCAN / LOOK 手算](../deep-dives/15-disk-scheduling-tutorial.md)

### 考法地图（2026-09-02 补 · 页式存储十种考法）

| # | 考法 | 核心套路 | 状态 |
|---|------|----------|------|
| 1 | 正向：逻辑→物理 | ÷页大小=页号，余数=页内；查表换帧；**偏移不变** | ✅ 已练 |
| 2 | 逆向：物理→逻辑 | ÷页大小=帧号；查表找帧对应页；页×页大小+页内 | 待练 |
| 3 | 位数三连 | 偏移位=log₂页大小；页号位=地址位−偏移位；页表长=2^页号位；页表占用=长×项大小 | 待练 |
| 4 | 访存次数 | **每过一张表 +1，最后取数 +1**：单级页 2 次、二级页 3 次、段式 2 次、段页式 3 次 | 待练 |
| 5 | 快表 TLB | 平均时间 = 命中率×(TLB+1 访存) + (1−命中率)×(TLB+页表+访存)；TLB 在 MMU 内不占访存 | 待练 |
| 6 | 缺页中断 | **内中断（故障）**；处理后**重新执行原指令**（非下一条） | 待练 |
| 7 | 页/段/段页对比 | 页=内部碎片；段=外部碎片；段好共享保护；地址：段号|页号|页内 | 笔记有 |
| 8 | 置换算法手算 | OPT/FIFO/LRU；FIFO 有 Belady 异常 | ✅ [13 号笔记](../deep-dives/13-page-replacement-tutorial.md) |
| 9 | 虚存容量（坑） | 虚存最大 = **2^地址位数**，不是内存+外存 | 待练 |
| 10 | 抖动/工作集 | 页框不足→频繁缺页→CPU 忙调页；对策：降多道程序度、按工作集分配 | 概念 |

陷阱：页表项位数 ≥ 帧号位数（物理地址位 − 偏移位），按字节对齐取整。

#### 位数三连 · 推导链（治「公式记不住」）

> 根本换算：**n 位 ↔ 2ⁿ 种**（10 位↔1024；12 位↔4096；20 位↔1M）。÷2ᵏ = 砍掉末 k 位（十进制 ÷100 砍末 2 位的二进制版）。

```text
页大小 4KB → 页内 4096 格，数清要 12 位   ⇒ 偏移位 = log₂(页大小)
地址 32 位 → 剩给页号 32−12 = 20 位       ⇒ 页号位 = 地址位 − 偏移位
页号 20 位 → 取值 2²⁰ 种 → 最多 1M 页     ⇒ 页表长度 = 2^页号位（每页一行）
每项 4B   → 1M × 4B = 4MB                ⇒ 页表占用 = 长度 × 项大小
```

- 关键一跳：页号有 20 位 = **取值有 2²⁰ 种**（不是数值 20）→ 每种取值一行 → 页表 1M 项
- 4MB 页表放不进连续内存 ⇒ **二级页表存在的理由**（考法 3 终点 = 考法 4 起点）
- 真题问法 ↔ 套环：偏移几位（第 1 环）／最多多少页、页表几项（第 3 环）／页表占多少（第 4 环）／页表项至少几字节（帧号位 = 物理位 − 偏移位，对齐取整）

#### 访存次数 · 推导（治「口诀没含义」）

> 核心事实：**页表本身放在主存里**（控制寄存器·页表地址指着它）——**查表这个动作本身就要先花一次访存**；
> CPU 内部的寄存器、快表 TLB 都不算访存。查一张表 = 读一个表项 = 一次访存。

```text
直接寻址：取数                                            = 1 次
单级页式：查页表① + 取数②                                 = 2 次
二级页式：查目录① + 查页表② + 取数③                       = 3 次
段式：    查段表① + 取数②                                 = 2 次
段页式：  查段表① + 查该段页表② + 取数③                   = 3 次
快表命中：TLB 在 CPU 内不占访存 → 只剩取数                 = 1 次
```

- n 级页表 → n+1 次；期望访存 = 命中率×1 + (1−命中率)×2（考法 5 公式的次数版）
- 跑腿记法：查一张表 = 跑一趟主存；取数 = 最后一趟
- 进阶坑：取指令本身也用逻辑地址要查表——「取指令+取一个操作数」单级页式 = 2+2 = 4 次

## 5. 总结
存储管理的核心在于地址转换的准确性和页面置换算法的选择。在复习时，应重点练习逻辑地址拆分、LRU 缺页计算和磁盘调度手算。
