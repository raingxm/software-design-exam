## 1. 子网块大小表（手算必背）

```text
/n   末字节掩码  块大小  可用主机   末字节切分（0 起）
/24     0        256     254      0
/25     128      128     126      0, 128
/26     192      64      62       0, 64, 128, 192
/27     224      32      30       0, 32, 64, 96, 128, 160, 192, 224
/28     240      16      14       0, 16, 32, ..., 240
/30     252      4       2        0, 4, 8, 12, ..., 252
```

**口诀**：掩码末字节 = 256 − 块大小；可用主机 = 块大小 − 2（去网络号 + 广播）

**判定同网**：两个 IP 各算**网络号**，相同 = 同网。

**速算**：从 /24 借 k 位 → **2^k 个子网**

## 2. 一道例题（手算演练）

> 192.168.1.**130**/27，求网络号、广播、可用范围。

```text
/27 → 块大小 32，末字节按 32 一跳切
0, 32, 64, 96, 128, 160, 192, 224
        ↑
        130 落在 128~159 块

网络号 = 192.168.1.128
广播   = 192.168.1.159
可用   = .129 ~ .158（30 个）
```

> 130.1 和 130.2 都在 128~159 → **同网**。  
> 192.168.1.160/27 → 网络号 160，**不同网**。

## 3. TCP 三次握手 / 四次挥手

```text
三次握手（建立）：
  客户端 → SYN → 服务端
  客户端 ← SYN+ACK ← 服务端
  客户端 → ACK → 服务端
  （建立完成）

四次挥手（断开）：
  主动方 → FIN → 被动方
  主动方 ← ACK ← 被动方
  主动方 ← FIN+ACK ← 被动方
  主动方 → ACK → 被动方
  （断开完成）
```

**为什么挥手 4 次？** TCP 是**全双工**，两边各关一次发送方向 → 各 1 FIN + 1 ACK，共 4 次。  
**握手能 3 次合并**：服务端把 ACK 和自己的 SYN 一起发。

## 4. TCP vs UDP 场景辨型

| 场景 | 用谁 | 理由 |
|---|---|---|
| 网页 / API（HTTP）| **TCP** | 不能丢字节 |
| DNS 查询 | **UDP** | 包小、允许重传 |
| 视频/语音实时 | **UDP** | 丢一点没事，迟了更糟 |
| 文件传输 / 邮件 | **TCP** | 必须完整 |
| Telnet / SSH | **TCP** | 远程命令不能丢字符 |

**口诀**：
- TCP = **可靠但不急**（握手/重传/排序都耗时）
- UDP = **急但不可靠**（发完不管）

## 5. 常见端口速记

| 端口 | 协议 | 用途 |
|---|---|---|
| **20/21** | FTP | 文件传输（21 控制 / 20 数据）|
| **22** | SSH | 安全远程登录 |
| **23** | Telnet | 明文远程登录，不安全 |
| **25** | SMTP | 发邮件（Simple Mail Transfer Protocol）|
| **53** | DNS | 域名解析（UDP）|
| **80** | HTTP | 网页明文 |
| **110** | POP3 | 收邮件，通常下载到本机（Post Office Protocol v3）|
| **143** | IMAP | 收邮件，信留在服务器，多设备同步同一邮箱（Internet Message Access Protocol）|
| **443** | HTTPS | 网页加密 |
| **3306** | MySQL | 数据库 |

**速记法**：
- **20-21** 拉文件（FTP）
- **22** 安全登录
- **25** 发邮件 (SMTP = **S**end **M**ail)
- **110** 收下来（POP3）：信通常下载到本机
- **143** 在线上看（IMAP）：信留在服务器，手机和电脑看的是同一份邮箱，已读和文件夹会同步。题干写「多设备同步看同一邮箱」→ IMAP / 143
- **53** 域名解析 (DNS)
- **80/443** 网页（明文/密文）
- **3306** MySQL

**易错点（2026-10-18 闭卷错题钉死）**：

- **25 = SMTP 发信**，不只是「客户端发出去」，**服务器与服务器之间投递邮件也走 SMTP 25**。题干写「发邮件 / 投递邮件 / 传输邮件」→ 25。
- **21 = FTP 控制连接**，别和 25 混。记法：20 多号段都是老式网络服务，`21` 搬文件、`22` 安全登录、`23` 明文登录、`25` 寄信（贴 2.5 毛邮票）。
- **收信才要二选一**：下载到本机 → POP3 / 110；多端同步、已读和文件夹一致 → IMAP / 143。题干写「收邮件」时不要出现 SMTP。
- 记忆锚：**110 是报警电话打进来**（收信），**143 在线上看**（信留服务器）。

## 6. 二层 / 三层与地址辨析

```text
帧 / MAC / 交换机 / VLAN tag → 数据链路层
IP 包 / IP 地址 / 路由器 / 路由 → 网络层
```

- IEEE 802.1Q VLAN tag 位于以太网帧中，属于**数据链路层**；跨 VLAN 通信才需要三层路由。
- IPv4 地址 32 位、IPv6 地址 128 位；常见 MAC 地址 48 位。
- IP 地址按网络拓扑进行层次化分配；传统 MAC 地址通常含厂商标识并由厂商分配。
- 唯一性要带作用范围理解：IP 在有效网络范围和同一时刻不能冲突；MAC 设计目标是唯一，但现实中可被修改、随机化或重复。不能说“IP 唯一而 MAC 不唯一”。
- ARP 完成 IPv4 地址到 MAC 地址的解析：**IP 跨网找方向，MAC 本地交到人**。

## 7. 加密场景速查

| 场景 | 用什么 | 关键 |
|---|---|---|
| **加密大量数据**（文件、磁盘）| **对称**（AES、DES）| 速度快 |
| **密钥分发 / 数字签名**| **非对称**（RSA、ECC）| 慢但解决"密钥怎么给对方"|
| **完整性校验**（文件没被改）| **哈希**（MD5、SHA-256）| 不可逆，定长输出 |
| **身份认证 + 完整性**| **数字签名**（私签 + 公验）| = 非对称 + 哈希 |
| **HTTPS 握手**| 非对称传密钥 + 对称传数据 | "混合加密" |

**口诀**：
- 加密/解密 = **对称快**、**非对称慢但能传密钥**
- 防篡改 = **哈希**（指纹）
- 既防伪又防改 = **数字签名**（私签公验）

**混合加密**（HTTPS）：
```text
客户端 → 服务端：我要 HTTPS
服务端 → 客户端：我的公钥（证书里）
客户端：用公钥加密一个「对称密钥」发给服务端
之后：双方用对称密钥通信（快）
```

## 8. 防火墙 / WAF / IDS / IPS

```text
以太网帧
└── IP 包（三层：源/目的 IP）
    └── TCP 段（四层：源/目的端口、连接状态）
        └── HTTP 请求（七层：URL、参数、Cookie、JSON）
            └── id=1 OR 1=1
```

- **传统包过滤 / 状态防火墙**：主要按 IP、端口、协议和连接状态放行或拒绝；两个请求都访问同一 `IP:443` 时，通常不理解哪个参数含 SQL 注入。
- **WAF（Web Application Firewall）**：重组 TCP 流并解析 HTTP/HTTPS，检查 URL、表单、JSON、Cookie 等应用层内容，可按 SQL 注入特征、参数类型和异常编码拦截请求。
- **HTTPS 前提**：普通旁路设备只看到密文；WAF 通常部署在 TLS 终止点，先解密再检查 HTTP 内容。
- **IDS**：侧重检测、记录、告警；**IPS**：串联部署，检测后主动阻断。
- **代码根治**：WAF 是外围防护，能拦截许多典型攻击但可能误报或漏报；SQL 注入仍应以参数化查询 / 预编译语句从根源防御。

**关键辨析**：数据包里承载了 HTTP 内容，**不等于**所有防火墙都会解析应用层语义；能否检查 SQL 注入取决于设备工作层次、协议解析能力以及能否解密 HTTPS。

**口诀**：网络防火墙问“这个 IP 能否访问这个端口”；WAF 问“这个 HTTP 请求是否恶意”；IDS 报警，IPS 拦截。

**变式验证（2026-10-17，`4/4`）**：

| 题干 | 结论 |
|---|---|
| 同一 `IP:443` 两个 HTTPS 请求，一个参数正常、一个含 `OR 1=1`，只部署传统防火墙 | 分不出来：按 IP/端口/协议/连接状态放行，不看应用层内容 |
| “检测到攻击并主动阻断” | **IPS**（IDS 只检测告警） |
| WAF 保护 HTTPS 站点，为何要放在 TLS 终止点 | 先解密才能拿到 URL、表单、Cookie 等明文内容 |
| “数据包承载了 HTTP，所以所有防火墙都能识别 SQL 注入” | **错**：承载 ≠ 能解析应用层语义 |
| 包过滤防火墙**不能**作为过滤依据的 | **HTTP 请求参数内容**（A 源 IP、B 目的端口、D 传输层协议都可以） |
