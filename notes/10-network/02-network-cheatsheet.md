## 1. 子网块大小表（手算必背）

```text
/n   末字节掩码  块大小  可用主机   末字节切分（0 起）
/24     0        256     254      0
/25     128      128     126      0, 128
/26     192      64      62       0, 64, 128, 192
/27     224      32      30       0, 32, 64, 96, 128, 160, 192, 224
/28     240      16      14       0, 16, 32, ..., 240
/30     252      4       2        0, 4, 8, 12, ..., 252
```

**口诀**：掩码末字节 = 256 − 块大小；可用主机 = 块大小 − 2（去网络号 + 广播）

**判定同网**：两个 IP 各算**网络号**，相同 = 同网。

**速算**：从 /24 借 k 位 → **2^k 个子网**

## 2. 一道例题（手算演练）

> 192.168.1.**130**/27，求网络号、广播、可用范围。

```text
/27 → 块大小 32，末字节按 32 一跳切
0, 32, 64, 96, 128, 160, 192, 224
        ↑
        130 落在 128~159 块

网络号 = 192.168.1.128
广播   = 192.168.1.159
可用   = .129 ~ .158（30 个）
```

> 130.1 和 130.2 都在 128~159 → **同网**。  
> 192.168.1.160/27 → 网络号 160，**不同网**。

## 3. TCP 三次握手 / 四次挥手

```text
三次握手（建立）：
  客户端 → SYN → 服务端
  客户端 ← SYN+ACK ← 服务端
  客户端 → ACK → 服务端
  （建立完成）

四次挥手（断开）：
  主动方 → FIN → 被动方
  主动方 ← ACK ← 被动方
  主动方 ← FIN+ACK ← 被动方
  主动方 → ACK → 被动方
  （断开完成）
```

**为什么挥手 4 次？** TCP 是**全双工**，两边各关一次发送方向 → 各 1 FIN + 1 ACK，共 4 次。  
**握手能 3 次合并**：服务端把 ACK 和自己的 SYN 一起发。

## 4. TCP vs UDP 场景辨型

| 场景 | 用谁 | 理由 |
|---|---|---|
| 网页 / API（HTTP）| **TCP** | 不能丢字节 |
| DNS 查询 | **UDP** | 包小、允许重传 |
| 视频/语音实时 | **UDP** | 丢一点没事，迟了更糟 |
| 文件传输 / 邮件 | **TCP** | 必须完整 |
| Telnet / SSH | **TCP** | 远程命令不能丢字符 |

**口诀**：
- TCP = **可靠但不急**（握手/重传/排序都耗时）
- UDP = **急但不可靠**（发完不管）

## 5. 常见端口速记

| 端口 | 协议 | 用途 |
|---|---|---|
| **20/21** | FTP | 文件传输（21 控制 / 20 数据）|
| **22** | SSH | 安全远程登录 |
| **23** | Telnet | 明文远程登录（不考）|
| **25** | SMTP | 发邮件 |
| **53** | DNS | 域名解析（UDP）|
| **80** | HTTP | 网页明文 |
| **110** | POP3 | 收邮件 |
| **143** | IMAP | 收邮件（同步）|
| **443** | HTTPS | 网页加密 |
| **3306** | MySQL | 数据库 |

**速记法**：
- **20-21** 拉文件（FTP）
- **22** 安全登录
- **25** 发邮件 (SMTP = **S**end **M**ail)
- **53** 域名解析 (DNS)
- **80/443** 网页（明文/密文）
- **3306** MySQL

## 6. 加密场景速查

| 场景 | 用什么 | 关键 |
|---|---|---|
| **加密大量数据**（文件、磁盘）| **对称**（AES、DES）| 速度快 |
| **密钥分发 / 数字签名**| **非对称**（RSA、ECC）| 慢但解决"密钥怎么给对方"|
| **完整性校验**（文件没被改）| **哈希**（MD5、SHA-256）| 不可逆，定长输出 |
| **身份认证 + 完整性**| **数字签名**（私签 + 公验）| = 非对称 + 哈希 |
| **HTTPS 握手**| 非对称传密钥 + 对称传数据 | "混合加密" |

**口诀**：
- 加密/解密 = **对称快**、**非对称慢但能传密钥**
- 防篡改 = **哈希**（指纹）
- 既防伪又防改 = **数字签名**（私签公验）

**混合加密**（HTTPS）：
```text
客户端 → 服务端：我要 HTTPS
服务端 → 客户端：我的公钥（证书里）
客户端：用公钥加密一个「对称密钥」发给服务端
之后：双方用对称密钥通信（快）
```
