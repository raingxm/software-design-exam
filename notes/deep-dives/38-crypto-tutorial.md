## 二、四类技术（先分清楚）

```text
加密      → 把明文变密文，防偷看（可还原）
摘要/哈希 → 指纹，防篡改（不可逆）
数字签名  → 证明「谁发的、没改过」（非 repudiation）
证书      → 证明「公钥确实属于某人」（CA 签发）
```

**易混**：哈希不是加密；加密能解密，哈希不能「解密」。

---

## 三、对称 vs 非对称加密

### 对称加密（一把钥匙）

```text
发送方 ──[同一密钥 K]──> 密文 ──[同一密钥 K]──> 接收方
```

| 项 | 说明 |
|----|------|
| 钥匙 | **加密和解密用同一把** |
| 算法 | DES、3DES、**AES**（常考） |
| 优点 | **快**，适合大量数据 |
| 缺点 | 密钥怎么安全交给对方？（密钥分发问题） |

**考试**：大量文件/报文加密 → 选 **对称**。

### 非对称加密（公钥 + 私钥）

```text
公钥加密 → 只有私钥能解
私钥加密 → 只有公钥能解（签名场景）
```

| 项 | 说明 |
|----|------|
| 钥匙 | **一对**：公钥公开，私钥自己保管 |
| 算法 | **RSA**（常考） |
| 优点 | 解决密钥交换、身份认证 |
| 缺点 | **慢**，不适合加密大文件 |

**考试**：
- 交换对称密钥 → 用 **非对称**（公钥加密密钥）
- 加密整封邮件正文 → 仍用 **对称**

### 数字信封（混合，HTTPS 同款思路）

```text
1. 随机生成对称密钥（会话密钥）
2. 用对称密钥加密正文（快）
3. 用接收方公钥加密对称密钥（安全送达）
4. 一起发送
```

**记**：**对称干重活，非对称送钥匙**。

## 四、哈希 / 摘要

| 项 | 说明 |
|----|------|
| 作用 | 生成固定长度「指纹」，检**完整性**（有没有被改） |
| 特点 | **单向**，不能从摘要反推原文 |
| 算法 | MD5、SHA-1、**SHA-256** |
| 场景 | 下载后比对哈希值；密码存库（存哈希不存明文） |

**考试**：「验证文件是否被篡改」→ **哈希/摘要**，不是加密。

---

## 五、数字签名

```text
发送方：对摘要用私钥加密 → 数字签名
接收方：用发送方公钥解密签名 → 比对摘要
```

| 保证 | 靠什么 |
|------|--------|
| 完整性 | 摘要 |
| 身份 / 不可抵赖 | **私钥签名**，公钥验证 |

**易混**：
- **加密**防窃听（保密性）
- **签名**防抵赖（谁发的、没改过）

签名时用的是 **私钥**，验证用 **公钥**（和「公钥加密、私钥解密」相反方向，别混）。

## 六、数字证书与 HTTPS（认场景）

| 概念 | 干什么 |
|------|--------|
| **CA**（证书颁发机构） | 第三方，给「公钥 ↔ 身份」做担保 |
| **数字证书** | 绑定了：持有者身份 + 公钥 + CA 签名 |
| **HTTPS** | HTTP + **SSL/TLS**；服务器证书证明「我是真网站」 |

浏览器访问 `https://` 时：证书验证身份 → 协商会话密钥（对称）→ 加密传输。

## 七、场景 → 技术（背这张表）

| 场景 | 选什么 |
|------|--------|
| 加密大量数据 | **对称**（AES） |
| 安全交换对称密钥 | **非对称**（RSA 公钥加密） |
| 检查文件/报文是否被改 | **哈希/摘要** |
| 证明消息是 A 发的、不能赖账 | **数字签名**（私钥签） |
| 证明网站公钥是真的 | **数字证书**（CA） |
| 网上银行 / 电商传输 | **HTTPS**（TLS + 证书 + 混合加密） |
