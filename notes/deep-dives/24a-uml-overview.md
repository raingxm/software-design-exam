## 一句话总入口

**UML = 把同一套系统从 4 个不同视角画出来，方便人和人沟通设计**。考试只考其中 4 张图（其它 10+ 张不考）。

## 4 张图对照

| 图 | 答的核心问题 | 一句话画风 | 试题三频度 |
|---|---|---|---|
| **用例图** | 谁（参与者）能用系统干什么（用例）？ | 人+气泡 | ⭐⭐⭐ |
| **类图** | 系统里有哪些「东西」，它们怎么连？ | 框+线 | ⭐⭐⭐ |
| **顺序图** | 做一件事的**时间顺序**是什么？ | 框+带箭头竖线 | ⭐⭐ |
| **状态图** | 一个**东西的生命周期**会经过哪些状态？ | 圆+箭头 | ⭐ |

**口诀**：**用例看人事、类看物线、顺序看时间、状态看物生**

## 同一系统 4 视角：图书馆借书

> 用一个系统走 4 遍，感受「同一件事 4 种切法」——这也是 UML 的真正价值。

### 1. 用例图（谁能做什么）

```
    读者(人)              图书管理员(人)
      │                       │
      ├── (查询图书)          ├── (图书入库)
      ├── (借书)              └── (维护读者)
      └── (还书)

      (借书)  ─ ─ include ─ ─>  (查询图书)
                  ↑ 借书必先查
```

**读图口令**：
- 参与者 = 人/外系统（方框或人形）
- 用例 = 椭圆/圆角框（写动词短语）
- 连线 = 参与者能触发该用例
- `include` 虚线箭头 = 必走子步骤
- `extend` 虚线箭头 = 可选触发
- 泛化 = 子 ──△──▶ 父（是一种）

### 2. 类图（系统里有什么、怎么连）

```
  ┌─────────┐            ┌─────────┐
  │  读者   │            │  图书   │
  ├─────────┤            ├─────────┤
  │-读者编号│            │-图书编号│
  │-姓名    │            │-书名    │
  └────┬────┘            │-状态    │
       │ 1               └────┬────┘
       │                      │ 1
       │ *                    │ *
       └────────┐    ┌────────┘
                ▼    ▼
            ┌──────────────┐
            │  借阅记录    │
            ├──────────────┤
            │-借阅日期     │
            │-应还日期     │
            └──────────────┘
```

**读图口令**：
- 类 = 方框（中间一条线分两部分：上类名、下属性）
- **线型决定关系种类**：
  - 实线 = 关联（最常见）
  - 实线空心三角 = 泛化/继承
  - 虚线空心三角 = 实现接口
  - 实心菱形 = 组合（强拥有，同生共死）
  - 空心菱形 = 聚合（弱拥有，可拆走）
  - 普通虚线箭头 = 依赖（临时用）
- 端点 `1` / `*` = 多重性

> 9/1 真题 14/15（数字图书馆）就是类图——靠「数类 + 看线 + 找空位」拿下的。

### 3. 顺序图（先做什么后做什么）

```
   时间   读者         系统         数据库
   ───────────────────────────────────────
   t1     │ 借书请求   │            │
          ├──────────> │            │
   t2     │           │ 查询图书状态│
          │           ├──────────> │
   t3     │           │   返回可借  │
          │           │ <──────────┤
   t4     │           │ 查询借阅数  │
          │           ├──────────> │
   t5     │           │  返回未超限 │
          │           │ <──────────┤
   t6     │           │ 创建借阅   │
          │           ├──────────> │
   t7     │ 借书成功  │            │
          │ <─────────┤            │
          ▼           ▼            ▼
```

**读图口令**：
- **纵轴 = 时间**（向下推进）
- **横轴 = 多个对象**（每个对象一条竖线，叫「生命线」）
- **实线箭头 = 同步调用**（带激活条 = 谁在干活）
- **虚线箭头 = 返回**
- 标在箭头上的文字 = 消息名（做了什么）

### 4. 状态图（一个东西一生的状态变化）

```
        ┌──┐
        │[*]│  起点
        └─┬┘
          │ 借书
          ▼
      ┌───────┐  到期未还   ┌───────┐
      │ 在馆  │───────────>│  借出  │
      └───┬───┘            └────┬───┘
          ▲   还书              │
          └─────────────────────┘

   借出 → 逾期未还 分支：
      ┌───────┐  归还+罚款   ┌───────┐
      │ 逾期  │<────────────│ 在馆  │
      └───────┘             └───────┘

   在馆 还有「报修 → 维修中 → 修复」分支，省略
```

**读图口令**：
- 起点 `[*]`（实心点），跟着箭头走
- **状态名 = 形容词/名词短语**（在馆/借出/逾期）
- **箭头上的词 = 触发事件**（借书/还书/到期未还）
- 终点 `[*]` 或 `┘`（牛眼）= 生命结束

## 真题开局三步（适用所有 UML 题）

1. **判图型**：题干/图本身告诉你是 4 张中的哪张（看到椭圆→用例、看到方框带属性→类、看到竖线带箭头→顺序、看到圆形带事件标签→状态）
2. **调视角**：只调那一张的读图口令，别混着用（顺序题用类图思路读就晕）
3. **找空位**：题干问题对应图上的空（C1~Cn、问答题空），按口令逐空填
