## 一、先搞清：TCP 和 UDP 各干什么？

两台机器传数据，需要**传输层协议**规定怎么送、可不可靠。

| | **TCP** | **UDP** |
|---|---------|---------|
| 中文 | 传输控制协议 | 用户数据报协议 |
| 连接 | **面向连接**（先握手再传） | **无连接**（直接发） |
| 可靠 | 确认、重传、有序 | 不保证到达、不保证顺序 |
| 速度/开销 | 慢一些、开销大 | 快、开销小 |
| 适用 | 网页、文件、邮件 | 视频、语音、DNS 查询 |

**考试口诀**：要可靠选 TCP；实时/广播/简单查询常 UDP。

## 二、三次握手（建立连接）

**目的**：客户端和服务器确认「双方都能收、都能发」，并协商初始序号。

```text
客户端                    服务器
   |  ① SYN（seq=x）          |
   | ----------------------> |
   |  ② SYN+ACK（seq=y,ack=x+1）|
   | <---------------------- |
   |  ③ ACK（ack=y+1）        |
   | ----------------------> |
   |      连接建立             |
```

| 步 | 谁发 | 标志 | 含义 |
|----|------|------|------|
| 1 | 客户端→服务器 | **SYN** | 「我想连你」 |
| 2 | 服务器→客户端 | **SYN+ACK** | 「收到，我也准备好了」 |
| 3 | 客户端→服务器 | **ACK** | 「收到你的确认，开传」 |

**记法**：SYN → SYN+ACK → ACK；**两次 SYN、两次 ACK**，共三步。

**易混**：握手是 **3 次**，挥手是 **4 次**（下面）。

---

## 三、四次挥手（释放连接）

**目的**：双方各自说「我发完了」，安全关闭。TCP 全双工，所以要两边各关一条方向。

```text
客户端                    服务器
   |  ① FIN                  |
   | ----------------------> |
   |  ② ACK                  |
   | <---------------------- |
   |  ③ FIN                  |
   | <---------------------- |
   |  ④ ACK                  |
   | ----------------------> |
   |      连接关闭             |
```

| 步 | 方向 | 标志 | 含义 |
|----|------|------|------|
| 1 | 客户端→服务器 | **FIN** | 「我不发了」 |
| 2 | 服务器→客户端 | **ACK** | 「知道你要关」 |
| 3 | 服务器→客户端 | **FIN** | 「我也不发了」 |
| 4 | 客户端→服务器 | **ACK** | 「知道，再见」 |

**记法**：FIN → ACK → FIN → ACK。

**为何 4 次？** 第 2 步 ACK 只确认「收到你的 FIN」；服务器可能还有数据要发，发完才发自己的 FIN（第 3 步），所以 ACK 和 FIN 常分两步。

## 四、TCP vs UDP 对照（背这张表）

| 对比项 | TCP | UDP |
|--------|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠 | 可靠 | 不可靠 |
| 有序 | 保证 | 不保证 |
| 速度 | 较慢 | 较快 |
| 首部 | 较长（20 字节起） | 较短（8 字节） |
| 场景 | HTTP/HTTPS、FTP、SMTP | DNS、DHCP、视频会议 |

## 五、常见端口（选择题常考）

| 端口 | 协议/服务 | 传输层 |
|------|-----------|--------|
| 20/21 | FTP（数据/控制） | TCP |
| 22 | SSH | TCP |
| 23 | Telnet | TCP |
| 25 | SMTP（发邮件） | TCP |
| 53 | DNS | **UDP 为主**（也见 TCP） |
| 80 | HTTP | TCP |
| 443 | HTTPS | TCP |
| 110 | POP3（收邮件） | TCP |
| 3306 | MySQL | TCP |
| 67/68 | DHCP | UDP |

**记法**：Web 80/443、远程 22、邮件 25/110、数据库 3306、域名 53。
