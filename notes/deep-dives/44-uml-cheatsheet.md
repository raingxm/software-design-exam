# UML 一页速记表

> 适用：软考中级软件设计师上午选择题 + 下午 UML 建模题  
> 用法：先背“图干什么 + 关系怎么判”，再去做 [UML 巩固演练](../../practice/drills/07-uml-drill.md) 和官方真题

---

## 1. UML 是什么

- UML = 统一建模语言
- 作用：把软件系统的**结构**和**行为**画出来
- 软考重点不是完整建模规范，而是：
  - 会认图
  - 会补图
  - 会判关系

---

## 2. 软考最常考的 4 类图

| 图 | 看什么 | 高频考法 |
|---|---|---|
| 类图 | 静态结构 | 关系辨型、补类名/属性/多重性 |
| 用例图 | 系统对外功能 | `include` / `extend` / 参与者 |
| 顺序图 | 一次交互的时间顺序 | 谁先调用谁、消息类型 |
| 状态图 | 一个对象的状态变化 | 状态、事件、转移 |

一句话：

```text
类图看结构，用例图看功能，顺序图看先后，状态图看阶段
```

## 3. 类图六种关系

### 总口诀

```text
临时用是依赖，长期有是关联
可拆开是聚合，同生死是组合
是一种是泛化，实现接口叫实现
```

### 3.1 依赖 `Dependency`

- 图形：`虚线箭头`
- 含义：临时使用一下对方
- 常见位置：方法参数、局部变量、返回值
- 题干信号：调用、借用、作为参数传入

例：

```text
OrderService.submit(payment)
```

判断口令：

- 没长期保存，只是这次办事用到 → 依赖

### 3.2 关联 `Association`

- 图形：`实线`
- 含义：长期知道或持有对方
- 常见位置：成员属性、对象引用
- 题干信号：有一个、拥有、保存、维护联系

例：

```text
Student 有 advisor: Teacher
```

判断口令：

- 作为字段长期存在 → 关联

### 3.3 聚合 `Aggregation`

- 图形：`空心菱形`
- 菱形位置：在整体端
- 含义：整体-部分，但部分可独立存在
- 题干信号：包含、由...组成，但拆开后部分还存在

例：

```text
Department ◇── Employee
```

判断口令：

- 整体没了，部分还可以单独活 → 聚合

### 3.4 组合 `Composition`

- 图形：`实心菱形`
- 菱形位置：在整体端
- 含义：整体-部分，强生命周期绑定
- 题干信号：删除整体时，部分随之消失

例：

```text
Order ◆── OrderLine
House ◆── Room
```

判断口令：

- 整体没了，部分脱离整体就没意义 → 组合

### 3.5 泛化 `Generalization`

- 图形：`实线 + 空心三角`
- 方向：`子类 -> 父类`
- 含义：继承，是一种
- 题干信号：继承、子类、父类、is-a

例：

```text
Dog ──△──> Animal
```

判断口令：

- X 是一种 Y → 泛化

### 3.6 实现 `Realization`

- 图形：`虚线 + 空心三角`
- 方向：`实现类 -> 接口`
- 含义：类实现接口
- 题干信号：接口、implements、遵守规范

例：

```text
Alipay - -△-> Payable
```

判断口令：

- 类对接口，不是继承类 → 实现

## 4. 两组最容易混的关系

### 依赖 vs 关联

| 对比 | 依赖 | 关联 |
|---|---|---|
| 关系长短 | 临时 | 长期 |
| 常见位置 | 参数/局部变量 | 成员属性 |
| 图形 | 虚线箭头 | 实线 |

一句话：

```text
方法里临时用 = 依赖
属性里长期放 = 关联
```

### 聚合 vs 组合

| 对比 | 聚合 | 组合 |
|---|---|---|
| 关系强度 | 较弱整体-部分 | 强整体-部分 |
| 生命周期 | 可分离 | 同生共死 |
| 图形 | 空心菱 | 实心菱 |

一句话：

```text
可拆开 = 聚合
同生死 = 组合
```

## 5. 类图判题流程

1. 先看是不是“是一种”
2. 若是：
   - 类到类 → 泛化
   - 类到接口 → 实现
3. 若不是，再看是不是整体-部分
4. 若是整体-部分：
   - 部分可独立存在 → 聚合
   - 部分不能独立存在 → 组合
5. 若也不是整体-部分，再看关系长短
   - 临时用 → 依赖
   - 长期持有 → 关联

## 6. 类图里的多重性

| 标记 | 含义 |
|---|---|
| `1` | 恰好 1 个 |
| `0..1` | 0 或 1 个 |
| `*` / `0..*` | 0 到多个 |
| `1..*` | 至少 1 个 |

读法：

```text
数标在哪端，就表示“对端 1 个对象，对应这一端几个对象”
```

易错点：

- 左右两端标反
- 没按“对端 1 个”去读

---

## 7. 下午类图补全题口令

1. **类名先从题干原词找**
2. 若题干没给原词，可用图结构 + 常识推断
3. **子类格只写特有属性**
4. 父类已有属性不要重复抄进子类
5. 看到 `Observer`、`Subject`、`Factory`、`Strategy` 这类命名时，顺手联想设计模式

## 8. 用例图速记

### 元素

- 参与者：系统外的人或外部系统，画在边界外
- 用例：系统提供的功能，画成椭圆
- 系统边界：系统职责范围

### 三种关系

| 关系 | 方向 | 含义 | 题眼 |
|---|---|---|---|
| `<<include>>` | 基础用例 -> 被包含用例 | 一定发生 | 必须先做、总是要 |
| `<<extend>>` | 扩展用例 -> 基础用例 | 条件发生 | 可选、例外、逾期才 |
| 泛化 | 子 -> 父 | 是一种 | 不同类型用户/支付方式 |

口诀：

```text
include = 必做片段
extend = 可选片段 / 例外流程
```

例：

- 取款 `include` 验证密码
- 还书 `extend` 缴罚款

## 9. 顺序图速记

- 核心：一次交互里谁先给谁发消息
- 总口令：

```text
上下是时间，左右是对象
```

常见元素：

- 生命线：对象的时间轴
- 激活条：对象正在处理
- 实线实心箭头：同步调用
- 虚线箭头：返回消息

易混点：

- 顺序图看多个对象之间的调用顺序
- 不看继承，不看状态阶段

---

## 10. 状态图速记

- 核心：一个对象从开始到结束经历哪些状态
- 总口令：

```text
状态图看自己处于什么阶段
```

常见元素：

- 初态：实心点
- 状态：圆角矩形
- 转移：箭头
- 事件：写在箭头上
- 终态：牛眼

例：

```text
待支付 -> 已支付 -> 已发货 -> 完成
```

---

## 11. UML 和 ER / DFD 的分界

| 图 | 关注点 |
|---|---|
| UML 类图 | 类、属性、方法、对象关系 |
| ER 图 | 实体、属性、联系、主外键 |
| DFD | 加工、数据流、数据存储、外部实体 |

一句话：

```text
类图是“对象怎么组织”
ER 是“数据怎么存”
DFD 是“业务怎么流”
```

## 12. 考前只背这几句

```text
类图看结构，用例图看功能，顺序图看先后，状态图看阶段。
临时用是依赖，长期有是关联，可拆开是聚合，同生死是组合。
子到父实线三角是泛化，类到接口虚线三角是实现。
include 一定发生，extend 条件发生。
子类只写特有属性，不重复父类已有属性。
```
