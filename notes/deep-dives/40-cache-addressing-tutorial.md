## 总口令

```text
Cache 容量 = 组数 × 路数 × 块大小（先算字节，再 /1024 换 KB）
地址总线送「第几号格子」，不送格子里的数据
n 根地址线 → 2^n 个门牌
按字节编址：一个门牌 = 1 字节 → 容量 = 2^n 字节
32 根 → 4GB（不要再除以 8）
tag 位数 = log₂(主存块数 ÷ Cache 组数)（2026-08-26 块 1 Q2 补）
```

---

## Cache 容量

组相联：Cache 分成若干**组**，每组有几个座位叫**路**。总容量要把路数乘进去。

摸底第 16 题：4 路、64 组、每块 32B。

\[
64 \times 4 \times 32 = 8192\text{B} = 8\text{KB}
\]

选成 4KB 就是漏乘 4 路。

---

## 寻址（门牌号）

内存是一排带门牌的格子。CPU 把门牌号经**地址总线**送出去。n 根线能拼 \(2^n\) 种号码。

软考默认按字节编址：一个门牌 = 1 字节，所以格子数 = 字节数。

\(2^{10}=1\)KB，\(2^{20}=1\)MB，\(2^{30}=1\)GB，故 \(2^{32}=4\)GB。

数据总线送的是格子里的内容，和「能点多少格」无关。除以 8 是把字节错当成位。

---

## 组相联 tag 位数（2026-08-26 块 1 Q2 补）

> 这是块 1 唯一漏的点：组相联下 **tag = 多少**？

**口诀**：

```text
tag 位数 = log₂(主存块数 ÷ Cache 组数)
         = log₂(每组可被映射的主存块数)
```

**直觉**：
- 主存有 M 块，Cache 有 S 组 → 平均每组"负责" M/S 块主存空间
- 这 M/S 块都得用 tag 区分（同一组内不同路靠 tag 识别）
- 所以 tag = log₂(M/S)

**块 1 Q2 实例**（4 路组相联，Cache 16KB / 块 32B / 主存 20 位地址）：
```text
Cache 组数 = 16KB / (4 路 × 32B) = 2^14 / 2^7 = 2^7 = 128 组
主存块数 = 2^20 / 32 = 2^15
tag = log₂(2^15 ÷ 2^7) = log₂(2^8) = 8 位 ✓
```

**避坑**：忘记乘路数 → Cache 组数算多 → tag 算少。

## 已过关

- 4 路 × 64 组 × 32B = **8KB**
- 32 位地址线、按字节编址 = **4GB**
- 概念：地址线送门牌号；按字节编址时格子数 = 字节数
