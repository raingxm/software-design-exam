## 口令

```text
虚线临时用=依赖；实线长期有=关联
空心菱=聚合（部分可独立）；实心菱=组合（同生共死）
实线三角=泛化/继承；虚线三角=实现接口
菱形在整体端；三角尖指向父类/接口
```

---

## 六种关系

| 关系 | 符号直觉 | 人话 | 题干信号 |
|------|----------|------|----------|
| **依赖** | 虚线箭头 | 临时用（参数/局部） | 方法里用到，无长期字段 |
| **关联** | 实线 | 长期知道对方 | 属性引用另一类 |
| **聚合** | 空心菱形 ◇ | 整体-部分，部分可独立 | 部门-员工；拆开部分还在 |
| **组合** | 实心菱形 ◆ | 整体-部分，强生命周期 | 房子-房间；整体毁部分毁 |
| **泛化** | 空心三角**实线** | 继承 is-a | 子类→父类 |
| **实现** | 空心三角**虚线** | 类实现接口 | implements |

松→紧（对象关系）：`依赖 < 关联 < 聚合 < 组合`

## 易混

| 对比 | 怎么分 |
|------|--------|
| 依赖 vs 关联 | 闪过一下 vs 字段长期握着 |
| 聚合 vs 组合 | 部分能否脱离整体独立存在 |
| 泛化 vs 实现 | 实线继承类 / 虚线实现接口 |

**多重性**：`1`、`0..1`、`*`、`1..*` 写在关联两端。

### multiplicity 怎么读（2026-08-27 补）

```text
数标在哪端 → 那端"被数 1 次"时，对端有几个
```

```text
  Course "*"  ──────  "1" Teacher
     │                  │
     ↓                  ↓
  1 个 Teacher        1 个 Course
  对应 * 个 Course     对应 1 个 Teacher
```

| 端标 | 含义 |
|---|---|
| `*` 或 `0..*` | 对端 1 个有 0 到多（最常见）|
| `1` | 对端 1 个正好 1 个 |
| `0..1` | 对端 1 个有 0 或 1 个（可选）|
| `1..*` | 对端 1 个至少 1 个 |

**易错**：左右端标反。每次写完用「1 个 X 端有几个 Y」反向验证。

### 关联类（2026-08-27 补）

**多对多关系上挂的"附加数据表"**。当两个类之间是 m:n，且需要存"这一对"的数据（如学员选课的成绩/时长），既放不到 A 也不放不到 B，就单独建一个类 C 挂在中间。

```text
Student * ────────── * Course       ← m:n 关系
       │             │
       └─────┬───────┘
             │
        StudyRecord                 ← 关联类：存"这一对"的数据
```

## UML 真题填空要点（2026-09-01 数字图书馆题 · 官方答案复判 14/15）

> 2024 上半年试题三首做：类名 9/9、模式满分，唯一扣分是子类重复父类属性。
> 判卷教训：先由模型盲判（估 7~9/15），后贴官方答案复判为 14/15——**图位相关判断以官方答案为准**。

1. **类名先从说明找原词；说明没有时，用图的泛化结构 + 常识推断**——本题 C1 是 User 与 Author（已给类）的共同父类 → Person（出题者疏漏，说明无原词；App 解析：User/Student/Faculty/Staff + Author 各挂三个子类是破题捷径）
2. **子类格只写特有属性**——继承的意义就是不重复；题目/作者/出版年份只写在父类格（本题唯一扣分点）
3. **属性按说明陈述直接提取**——说明写「保存了题目、作者、出版年份」→ C6 属性含作者（即使 Author 同时是类）
4. 模式识别看图线索：`observed by` 关联、Observer 类名 → 观察者模式 + 对应用例
