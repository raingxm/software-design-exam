## 暴露的问题与订正

### 1. DFD：信息来源没有分层核对

- 外部实体和数据存储识别正确；缺失数据流只稳定找出 `P4 → D2：订单状态`。
- 其余参考数据流为：`P3 → E3：餐单`、`P3 → P4：订餐请求`、`P5 → E3：配送码`。
- `P3 → E3：餐单` 来自上下文图与 0 层图的平衡检查；`P3 → P4：订餐请求` 来自处理之间的触发与交接；`P5 → E3：配送码` 来自题干业务叙述，不是上下文图。上下文图中没有“配送码”，不能错误地用父子图平衡解释它。
- 今后按三轮检查：先核对上下文图输入输出，再沿业务处理链检查触发流，最后回读题干中尚未落图的名词和动作。
- “结构化语言”此前不熟悉，现已明确可用顺序语句、`IF—THEN—ELSE—ENDIF` 和 `WHILE—DO—ENDWHILE` 表达处理逻辑。

### 2. 数据库：未看清“补图 + 关系模式”的双重要求

- 第 2.1 问漏掉“被接种者—医院—供应商”的三元接种联系及“接种日期”属性，只画成了医院与被接种者的二元多对多联系。
- 第 2.2 问关系模式的主键、外键总体正确。
- 第 2.3 问图形部分基本识别正确：新增“被检测者”实体及姓名、身份证号、地址、电话属性；新增“检测”联系及检测日期、检测结果属性；医院与被检测者为多对多。
- 失分关键是没有继续写新增关系模式：
  - `被检测者(身份证号, 姓名, 地址, 电话)`，主键为身份证号；
  - `检测(被检测者身份证号, 检测日期, 医院名称, 检测结果)`，按“每天一次”取主键 `(被检测者身份证号, 检测日期)`，并设置指向被检测者和医院的外键。
- 已澄清：E-R 图中矩形表示实体、菱形表示联系、椭圆表示属性；“补充实体联系图”可能要求补实体、联系、属性、基数，也可能同时要求把新增内容转换成关系模式。机考必须逐字看清每个动词。

### 3. UML：会认图，但概念定义不够准确

- 6 个用例识别正确；类的属性基本正确，类操作补充不完整。
- `include`：抽取多个用例中公共且必然执行的行为，执行基本用例时必须执行被包含用例。
- `extend`：在特定条件下为基本用例附加可选行为，基本用例本身可以独立完成。
- “某用例是另一用例的一种特殊情况”描述的是泛化倾向，不是 `extend` 的定义。原图关系即使显得牵强，也应优先回答题目所问的两种关系的一般含义，不强行替图找理由。

### 4. 算法 C：数组声明、复杂度与手算效率均需加强

- 第 4.1 问 4 空答对 3 空；错误空把 `seq` 当成二维数组。函数参数已经声明为 `int seq[]`，它是一维维数序列。
- 若 `seq = [15, 5, 10, 20, 25]`，则 `A1=15×5`、`A2=5×10`、`A3=10×20`、`A4=20×25`；转移式乘法项为 `seq[i] * seq[k+1] * seq[j+1]`。
- 第 4.2 问算法类型“动态规划”正确，时间复杂度误写成 `O(n²)`。共有 `O(n²)` 个区间状态，每个状态枚举 `O(n)` 个断点，因此时间为 `O(n³)`；精确的断点枚举次数为 `n(n-1)(n+1)/6`，空间为 `O(n²)`。
- 第 4.3 问正确答案为 `A1*((A2*A3)*A4)`，最少乘法次数 `5375`。考试中使用按链长填写的三角表，不要重新枚举所有完整括号方案：
  - 长度 2：`750, 1000, 5000`；
  - 长度 3：`cost[0,2]=2500`，`cost[1,3]=3500`；
  - 长度 4 的三个候选为 `5375, 9500, 10000`，取 `5375`。
- “优先在最小维数附近切分”只能帮助猜测，最终仍须代入候选式验证。

### 5. Java：模式理解较稳，但必须逐字服从源码

- 备忘录模式的对象关系和其余 5 个空正确。
- 源码形参是合法但不规范的 `Memento Memento`：前者是类型，后者是变量名。因此调用必须写 `Memento.getState()`；写成习惯性的 `memento.getState()` 会因 Java 严格区分大小写而失分。
- 填空完成后增加机械复查：已声明标识符、大小写、方法名、数组下标和括号必须与题面完全一致。
