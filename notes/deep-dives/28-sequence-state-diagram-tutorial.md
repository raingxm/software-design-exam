## 一、序列图（用「下单付款」看懂）

对象：顾客 · 订单系统 · 支付系统  

```text
   顾客              订单系统            支付系统
    |                  |                   |
    | ---- submit() -->|                   |  ① 同步消息（实心箭）
    |                  |====|              |  ② 激活条：订单在干活
    |                  |    |-- pay() ---->|  ③ 再调支付
    |                  |    |              |====|
    |                  |    |<- - 成功 - - |     ④ 返回（虚线箭）
    | <- - 下单成功 - -|                   |  ⑤ 回给顾客
   时间 ↓
```

| 元素 | 人话（打电话类比） |
|------|-------------------|
| 生命线 | 每个角色一条时间轴 |
| 激活条 | 正在处理（听筒还拿着） |
| 同步消息 | 打电话等对方办完（实心箭） |
| 异步消息 | 发微信不等回（开放箭） |
| 返回消息 | 把结果捎回来（虚线；可省略） |
| «create» / X | 新建对象 / 生命线末端销毁 |

**和类图**：类图看结构关系；序列图看一次交互的时间顺序。

## 二、状态图（用「订单一生」看懂）

```text
 ●──▶ (待支付) ──支付成功──▶ (已支付) ──发货──▶ (完成) ──▶ ◉
初态     状态       事件         状态      事件    状态      终态
```

| 元素 | 人话 |
|------|------|
| 状态 | 对象待在哪个阶段（圆角框） |
| 转移 | 因事件离开（箭） |
| 事件 | 箭上的字，如「支付成功」 |
| 守卫 | `[金额>0]` 条件为真才跳 |
| 初态 / 终态 | 实心点 / 牛眼 |

**和序列图**：序列=多对象互相呼叫次序；状态=一个对象自身阶段变化。
