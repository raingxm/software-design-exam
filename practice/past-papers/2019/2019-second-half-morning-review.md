## Q50 勘误（2026-10-20）

**原记录「正解 C」有误，正确答案是 B `(0|10)*`，用户原作答 B 正确。**

图为两状态自动机：`q0` 既是起始又是终态（双圈），`q0` 有 `0` 自环，`q0 --1--> q1`，`q1 --0--> q0`，`q1` 为单圈且只有一条出边。

从 `q0` 出发回到 `q0` 的环路只有两条：`0`（长度 1）与 `10`（长度 2）。因此语言为 `(0|10)*`。

程序穷举长度 0～8 的全部 `01` 串验证：

| 选项 | 是否等价 | 差异例 |
|---|---|---|
| A `(0\|1)*` | 否 | 图拒绝 `1`，A 接受 |
| **B `(0\|10)*`** | **是**（88/88 全同） | 无 |
| C `0*(10)*` | 否 | 图接受 `100`、`0100`、`1000`，C 仅接受 25/88 |
| D `0*(1\|0)*` | 否 | 同 A |

**教训**：题库参考答案与题图冲突时，以图为准；看图时必须先确认「终态在哪」以及「回到终态的那个状态还能读什么」。本题若按三状态机器（C 的形态）理解，就会把 `10` 之后的出口当成不能读 `0`，从而误判。

**考场两探针**：先试 `1`（排除 A、D），再试 `100`（排除 C），只剩 B。

## 答对但不确定题复盘（2026-10-20）

### Q41：UML 状态迁移（已理解）

- 原答与正解均为 C。
- 迁移的标准写法是 `触发事件 [监护条件] / 动作`，可记为「发生什么［是否允许］/ 顺便做什么」。
- 源状态和目标状态是迁移连接的两个端点，不是迁移“包含”的成分；题目 C 把“动作”错写成“状态”。
- 无监护条件表示不需要额外判断，触发事件发生后可以直接迁移。
- 复测 `登录中 -- success [attempts < 3] / recordLogin() --> 已登录`：用户能正确识别监护条件、动作和两端状态，经提示后将触发事件由“登录”订正为 `success`。

### Q44、Q46：Bridge 桥接模式（已理解）

- Q44 原答与正解均为 C（Bridge）；Q46 原答与正解均为 A（不希望抽象与实现之间存在固定绑定）。
- 识别信号：系统同时存在两个需要独立变化的维度，例如「图形种类」与「绘图实现」。
- 若只用继承，会形成 `V1Circle`、`V2Circle`、`V1Rectangle`、`V2Rectangle` 等组合爆炸；桥接改用组合，让抽象对象持有实现接口，两边可独立扩展并自由组合。
- Java 结构已过：`Shape` 持有 `DrawingAPI`；`Circle`、`Rectangle` 扩展抽象；`V1DrawingAPI`、`V2DrawingAPI` 实现绘图接口。用户能够指出“可以独立变化”是本题核心。
- 模式边界：桥接是主动拆分两个变化维度；适配器是事后转换不兼容接口；装饰器是动态增加职责；组合模式表示部分—整体树形结构。
